== What this is, and how it works

Harvard Dehallucinator keeps an LLM agent's task state outside its context
window. Its one piece of project-specific code is a state engine,
`engine/Engine.hs` (Haskell, run with `runghc`), and a verifier,
`engine/verify_register.sh`. The engine's guarantee is that `COMPLETE` is only
ever derived from the verifier's measured count, never from an argument the
caller supplies. Everything else in the tree is RSR template scaffolding. This
file reports what the repo's own checks printed against one commit on
2026-10-07. It supersedes the 2026-08-25 file, which was an unfilled template
and is now at `docs/affirmations/AFFIRMATION-2026-08-25.adoc`.

=== The honest nuance you must not lose

* *The guarantee is about the engine's interface.* The suite shows that no
  command-line argument can produce `COMPLETE`. It does not show that an agent
  with write access to `state/state.txt` or to `engine/verify_register.sh`
  cannot forge it.
* *The ABI and the proofs are template material.* `src/interface/Abi/` and
  `verification/proofs/` came from `rsr-template-repo`, and the Coq file says
  "Replace with your project's type system proofs". A green build of them is
  not evidence about this project.
* *The Lean toolchain differs from its pin.* The run used Lean 4.34.1, while
  `verification/proofs/lean4/lean-toolchain` pins `v4.15.0`.

=== Known-incomplete but honestly fenced
